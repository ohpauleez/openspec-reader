# Design and invariants

Content scripts handle local Markdown, Alloy `.als`, Java `.java`, and OpenJML `.jml` file URLs; the Firefox background script handles optional website injection. Both render into the existing text document. The original URL and base URL are retained. The source is captured once, before changing the DOM. No filesystem service, upload, or native helper is involved.

Lifecycle: plain text → source captured → parsed → rendered. Injection is idempotent. A failed parse leaves the original source visible. Rendering enhancements can fail independently without losing prose or code.

The deterministic core parses Markdown tokens into sections, source ranges, code fences, and OpenSpec identities. All nested sections end at the next heading of equal or lesser depth. IDs are unique even for repeated headings. Only real headings and text tokens participate in OpenSpec recognition; code and raw HTML never become requirements or keyword annotations.

EARS clause formatting is a source-preserving inline-token transform. It inserts presentation breaks before uppercase clause starters and underlines only the complete `<system>` name, excluding `THE` and its following whitespace. `THE <system>` and the modal response stay on the same line. Tokens are split within, never across, emphasis/link/code boundaries; headings, literal code, and raw HTML are not reflowed. Existing explicit line breaks are not duplicated.

Markdown, standalone Alloy, and Java/JML have distinct document-model variants. Source files never enter the Markdown/EARS pipeline. Alloy uses a comment/string-aware lexer to index top-level declarations outside balanced braces, parameter brackets, and parentheses. Java uses the same structural parser as its CodeMirror language to index types and members, with parameter types disambiguating overloads; specification-only model/ghost declarations are indexed from actual JML comment regions. Every outline entry has a unique fragment and a source offset/line in the normalized editor text. Raw source remains intact; BOM/CRLF normalization affects only displayed editor offsets. The same read-only code-view implementation powers fences and whole source files. Outline and search targets reveal their source locations, including from raw-source view; large-source text fallbacks retain offset navigation.

Javadoc/JML comment regions come from Java syntax nodes, never from annotation-looking string contents. Consecutive line annotations are grouped only when their conditional markers agree. Full-line comment blocks can be replaced by collapsible view-only cards; inline modifiers remain source text. Javadoc HTML is sanitized, literal/code tags are escaped, and only unambiguous in-file member references become generated fragments. JML expressions are rendered as text tokens; quantifier semicolons are not clause separators. Each card exposes original source, and annotated-source mode removes the card replacements entirely. The EditorState document is never rewritten. Fold replacements take precedence over comment cards, and navigation can unfold source and reopen its card. Rendering is independent of Java compilation or OpenJML verification.

Comment ownership is retained as explicit metadata so headers can identify qualified declarations. A first-sentence summary is extracted from sanitized prose DOM with a Range, preserving inline markup and the remaining description. Inline literal punctuation is excluded from sentence detection. Documentation card width is bounded by the visible editor width rather than the widest source line, and cards remain horizontally visible as code pans.

Documented simple enums are classified from Java syntax nodes and shown as source-mapped constant/documentation tables. Behavioral enums, inline declarations sharing a source line, and enums containing JML specifications retain normal source rendering. Table replacements cannot overlap comment cards or folded regions. Original text remains in EditorState and the source disclosure; outline/search navigation can reveal individual rows.

A view-local horizontal control mirrors each overflowing editor/fallback or raw-source scroll position while its native scrollbar is offscreen. Geometry and thumb position follow scrolling, resizing, folding, and presentation changes. The control does not scroll the page vertically, and its listeners/observers are removed with the reader.

CodeMirror views are read-only. Native parsers supply structural folding for JS/TS, Java, and Rust. Alloy uses a lexical scanner that excludes strings and comments when matching braces; comment blocks are separately foldable. Folding changes presentation, never source. Saved code offsets are applied only to identical fence content. Editors are mounted near the viewport and destroyed on page exit.

All document HTML and rendered SVG pass through DOMPurify. Mermaid uses strict security mode with a bounded diagram size. Document-provided IDs cannot shadow reader controls. Reader dependencies are packaged locally; no CDN or remote code is used. Remote images explicitly referenced by Markdown retain normal browser loading behavior.

Mermaid renders in a dedicated temporary measurement container to retain complete SVG namespaces and participant groups, using global SVG text labels so sanitization does not discard HTML labels. Zoom changes explicit SVG/canvas dimensions rather than applying CSS zoom to percentage-sized SVGs. Scale remains between 25% and 400% of fitted size; Shift+wheel preserves the pointer's diagram location as far as scroll bounds permit, and unmodified wheel events retain normal browser scrolling. Resize observers are disconnected when the reader is destroyed.

Reading state is bounded to 40 documents, 2,000 section entries per document, and 2,000 code ranges. Documents over 8 MiB retain the browser's original text view. Very large fences use a plain text fallback rather than instantiating an editor. Source excerpts are not stored in preferences or reading state.

Checks: strict TypeScript; parser and diagnostics examples; property-based section and Alloy folding invariants; integration tests on the supplied OpenSpec corpus; real Firefox extension smoke tests for file URLs, folding, navigation, persistence, Mermaid, and sanitization. Bounded checks are evidence for their exercised inputs, not a proof of browser behavior.

## Alloy exploration

The explorer is an extension-owned page launched from captured `.als` sources or explicitly selected Markdown fences. Its import, typed trace representation, graph/table renderers, lasso playback, profile, and save/export paths are independent of any analysis provider. Imported XML is validated before replacing active evidence; states are never flattened. Both `backloop` and `looplength` formats are normalized to a loop-state index. Signature inheritance is expanded topologically with a total membership budget. Every n-ary tuple retains column ordering; graph limits/projection never rewrite table data.

### ShiViz-inspired Timeline

Timeline is a native TypeScript/SVG behavioral lens over captured Alloy evidence. The local ShiViz reference informed lane headers, synchronized narrative/event diagrams, reversible local-event collapsing, hide/focus menus, motif navigation, and whole-execution comparison. Existing explorer themes, signature/relevance colors, source links, playback and inspector are reused; no ShiViz page, vector-clock log parser, jQuery runtime or external service is embedded.

`timeline-model.ts` derives immutable evidence-backed events from the cached transition deltas. Every event retains its original declaration, full tuple columns, change direction and stored-state coordinates. Most-specific primitive membership is indexed independently of XML declaration order. Interpretation mappings only decorate/group recorded facts; mapped labels and present relation values have separate provenance from observed changes. Predicate execution, physical time, send/receive ordering and happened-before are never inferred from generic state differences. XML retains a static/temporal/unknown discriminator; native `isTemporal()` metadata disambiguates one-state results. Snapshots have initial context only, while explicit temporal self-loops retain a closing stutter band.

The shared inspector has explicit workspace ownership: none, shared atom selection, or Timeline-specific content. Leaving Timeline clears Timeline-owned DOM so its pane releases layout width in Graph/Table/Source/Adjacent states. Event selection may remain in Timeline's own model; restoring its details reclaims ownership. Initial-state, lane and motif panes also claim ownership even without a retained event. Shared atom selection supersedes retained Timeline event selection and remains valid across view switches. Loading a new result or clearing the trace resets inspector ownership.

`timeline-profile.ts` validates bounded declarative mappings, lane/group preferences, search and graphical pattern nodes. Templates interpolate tuple columns without executing code. Layout has fixed participant columns and atomic transition bands; no internal causal order is implied by event placement. Hiding/grouping lanes never drops tuple evidence or creates unsupported transitive edges. Local-only collapse retains underlying transition IDs, exempts interactions/search selections, and never crosses a loop boundary. Selecting a collapsed group selects its first actual transition. Both source and destination indices are retained for loop-target selection and shared Graph/Table differences.

`timeline-diagram.ts` virtualizes rows and columns, rendering viewport-sized SVG fragments rather than a giant SVG for all participants. Narratives and diagrams share row geometry and a scroll surface; sticky headers, stable lane order and saved scroll positions preserve orientation. Summary detail and the eight-glyph per-band viewport bound are separate from complete paginated evidence inspection. Follow-playback is distinct from manual scrolling. Visible-window SVG export includes embedded theme colors, headers, narrative text and an explicit viewport label.

`timeline-search.ts` compiles bounded field/boolean queries, quoted text and regular expressions. Matching runs in a disposable module worker with a 1.5-second deadline, cancellation and stale-result guards. It searches original hidden/collapsed events and both comparison executions. Counts cover all matches; navigation is capped at 10,000 with explicit reporting. `timeline-analysis.ts` supplies bounded 1–4-node ordered-variable pattern matching, tuple-topology and explicitly correlated communication candidates, structural motif discovery and execution grouping. No state-order pattern is presented as proof of causality. Motif keys use compact interned transition structures; the execution library loads on demand under a 24 MiB XML budget.

Comparison aligns by stored index or bounded event-sequence LCS. Structural agreement is tentative until unique stable Int/String identity fields or explicit one-to-one participant confirmations support it; printed atom names alone never establish identity. Unmatched/gap bands remain explicit, aligned lane headers mark tentative correspondence, and loop-target differences are retained. User confirmations clear on a new solver result or baseline, while saved artifacts restore their exact comparison evidence and confirmations. Optional baseline XML/profile metadata extends version-1 bundles compatibly and is parsed before replacing active evidence. Baseline inspection/source always uses the baseline's captured data, never the current trace's provenance.

Atom coordinates persist within a trace and reset for independent solutions. Playback records its actual predecessor, including the last-to-loop transition; backtracking uses bounded history. Atom inspection follows the selected state. Watches report their stored trace position explicitly. Counterexamples are labeled by command outcome; the renderer does not invent a unique causal event or a first failing state for arbitrary temporal formulas.

The optional native provider uses Firefox native messaging to a TypeScript host. A small Java binding uses the project's official Alloy 6 parsing/translation/solution APIs. Native permission is optional and requested only by Connect. Each workspace owns its JVM, incremental solution, and source bundle. The host captures project modules in a temporary directory, overlays reader/fence sources, preserves module paths, and records source/bundle/JAR hashes. Project files are read-only. Source selection changes invalidate controls; loading a new model does not relabel old displayed evidence. Solver errors, UNSAT results, timeout, cancellation, and enumeration exhaustion have distinct states.

Requests are length-bounded/correlated, with one active engine operation per workspace and an independent cancel path. Timeouts/cancel/disconnect stop the solver (including Unix process-group children); compilation is abortable. Captures/temporary files and listeners are cleaned up. Saved bundles retain XML/source/provenance and declarative preferences, never executable visualization scripts. Browser-only execution is not advertised: a SAT WASM module alone does not implement Alloy's frontend, relational/temporal encoding, decoder, enumeration, or evaluator.

Whole-file `.md` execution preserves a filename hint and the complete original document as a single model part. The bridge snapshots Markdown alongside `.als` files and delegates literate parsing to the project's Alloy JAR. Source and diagnostic coordinates therefore refer to the original document, without a plugin-specific fence extraction or synthetic line offset. Uploaded-root switching and saved-bundle restoration preserve this format. Extracted fences continue using virtual `.als` roots; a `.md` source URL is not sufficient to change their execution format.

Graph layout uses a locally bundled ELK worker, with layered/directional and force-directed modes. The bounded layout topology is the visible trace-union by default, with separate nodes for higher-arity tuple junctions and individually labeled argument edges; only actual current/difference tuples are rendered. Playback and comparison share coordinates and never trigger arrangement. Current-state arrangement is an explicit alternative. Relation layout influence is independent of relation visibility. Manual pins are fixed obstacles in a post-layout collision sweep; routes whose endpoints move use clipped, separated fallback curves until a suitable automatic route is available. Replacement models, visibility changes, manual edits and new requests abort pending workers, and a 15-second deadline bounds layout work. Geometry/settings/pins/routes are validated declarative data in optional version-1 bundle metadata, so existing saved explorations remain compatible.

Signature colors use a shared pure resolver for SVG, editable sidebar, and graph legend. A model-scoped registry keys primitive signatures/subsets by qualified label and kind, independent of XML IDs; built-in colors are reserved separately. All primitive signatures, including empty/hidden signatures, participate in allocation. Each signature has a trace-relevant variant (soft primary families and pastel lavender) and an unrelated-static-context variant (saturated purple/magenta families). Color relevance is separate from direct change detection: a weak trace cache unions tuple and non-builtin membership changes over the full trace, including the loop, then adds exactly one tuple hop of fixed supporting context with complete argument lists. Static and single-state results make every observed atom relevant; empty signatures default to soft colors. These roles are independent of focus/visibility settings and remain fixed throughout playback. Mixed signatures expose both variants in the legend. Existing nonconflicting assignments are retained; new ones use role-specific categorical palettes followed by bounded greedy max-min OKLab separation over role-constrained HSL lattices converted to sRGB. Soft lavender and vivid purple are separated by lightness/saturation rather than excluding lavender hues. Neither family wraps or collides with the other within the supported 2,000-declaration bound. Explicit user colors may coincide intentionally and apply to both roles. Styling resolves explicit applicable subset overrides first (qualified-name order), then primitive and inherited ancestor overrides, then the signature's role-specific automatic fill. Default subset membership is an annotation, not an arbitrary type-color replacement. Black/white text maximizes contrast against the opaque fill; temporal differences use symbols/borders instead of fading fills. The optional profile color registry is validated and saved with existing version-1 bundles. Palette revision `trace-role-v2` migrates earlier automatic defaults, including v1, once while retaining manual overrides and migrating legacy declaration-ID overrides. New-model identity resets color overrides; additional solutions and same-model XML imports retain both variant assignments. This preserves Alloy Analyzer's type/set inheritance semantics while extending its automatic color allocation.

Trace focus indexes non-builtin membership deltas and exact tuple deltas across every adjacent state plus the closing lasso edge. Indexes are weakly trace-cached; presentation selections are memoized using immutable focus/filter references. Whole-trace relevance is stable throughout playback, while step focus uses the actual incoming transition (initially the outgoing transition). One-hop context expands from a fixed set of changing/always-show seeds, adding whole original tuples without recursive closure. Graph visibility, tuple rendering, automatic layout and fit use the same selection; adjacent panes share it and tables retain full values. Context-only links may be hidden without changing evidence. Focus overrides do not imply coordinate pins and never override ordinary signature/projection filters or state existence. Relevance, colors, and coordinates have separate ownership. Focus changes preserve existing coordinates; missing coordinates are placed near established neighbors. Static/empty relevance falls back to the full instance with an explicit explanation. Optional validated profile metadata preserves backward-compatible version-1 bundles; overrides are bounded to 20,000 atoms and relation selections to the existing declaration bound.
